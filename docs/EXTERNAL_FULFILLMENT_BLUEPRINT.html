01

DeliveryFulfillmentProvider

This sits above DriverAssignmentStrategy from the Engine Interfaces Blueprint, §07 — that interface answers "which of our own riders." This one answers "our own fleet, or someone else's." The in-house path becomes one implementation among several, not a special case the rest of the system has to know about.

DeliveryFulfillmentProvider.javaProposed
public interface DeliveryFulfillmentProvider {
    FulfillmentQuote quote(Order order);
    FulfillmentHandle handOff(Order order);
    void cancel(FulfillmentHandle handle);
    FulfillmentSource source();
}

public enum FulfillmentSource { IN_HOUSE, RAPIDO, SHADOWFAX, PORTER, DUNZO }

// value object — same shape regardless of who ends up delivering
public record FulfillmentHandle(
    FulfillmentSource source,
    String externalTaskId,   // null for IN_HOUSE — driverId lives on the Order/TripDetail instead
    Long driverId
) {}

public record FulfillmentQuote(
    FulfillmentSource source,
    BigDecimal fare,
    int etaMinutes
) {}
InHouseFleetProvider.javaWraps existing logic
@Component
public class InHouseFleetProvider implements DeliveryFulfillmentProvider {

    private final DriverMatchingEngine matchingEngine;              // Engine Interfaces Blueprint §06
    private final List<DriverAssignmentStrategy> assignmentStrategies; // §07

    @Override
    public FulfillmentQuote quote(Order order) {
        // no per-order quote step today — delivery charge is already fixed
        // at checkout by PricingOrchestrator, so this is informational only
        return new FulfillmentQuote(FulfillmentSource.IN_HOUSE, order.getDeliveryCharge(), null);
    }

    @Override
    public FulfillmentHandle handOff(Order order) {
        List<RankedDriver> ranked = matchingEngine.rank(order);
        AssignmentOutcome outcome = assignmentStrategies.get(0).assign(order, ranked);
        return new FulfillmentHandle(FulfillmentSource.IN_HOUSE, null, outcome.driverId());
    }

    @Override
    public void cancel(FulfillmentHandle handle) {
        // delegates to the existing admin/rider cancellation path — no new logic
    }

    @Override
    public FulfillmentSource source() { return FulfillmentSource.IN_HOUSE; }
}
02

FulfillmentRoutingStrategy

The decision of which provider handles a given order — kept separate from the providers themselves, so "when do we go external" stays a tunable policy, not logic buried inside RapidoDeliveryProvider.

HybridRoutingStrategy.java + DeliveryOrderService.java (excerpt)Dummy code
@Component
public class HybridRoutingStrategy implements FulfillmentRoutingStrategy {

    private final List<FulfillmentRoutingStrategy> delegates; // zone, then capacity, then cost

    @Override
    public FulfillmentSource decide(Order order, FulfillmentContext ctx) {
        return delegates.stream()
                .map(s -> s.decide(order, ctx))
                .filter(Objects::nonNull)
                .findFirst()
                .orElse(null);  // null → DeliveryOrderService falls back to IN_HOUSE
    }
}

@Service
class DeliveryOrderService {

    private final List<FulfillmentRoutingStrategy> routingStrategies; // just HybridRoutingStrategy today
    private final Map<FulfillmentSource, DeliveryFulfillmentProvider> providers;

    void dispatch(Order order) {
        FulfillmentContext ctx = contextFor(order); // zone, idle-driver count, live quotes

        FulfillmentSource source = routingStrategies.stream()
                .map(s -> s.decide(order, ctx))
                .filter(Objects::nonNull)
                .findFirst()
                .orElse(FulfillmentSource.IN_HOUSE); // safe default, never silently unassigned

        DeliveryFulfillmentProvider provider = providers.get(source);
        FulfillmentHandle handle = provider.handOff(order);
        tripDetailService.recordFulfillment(order, handle); // extends the existing TripDetail entity
    }
}
03

Rapido — dummy implementation

Four pieces: the provider itself, a thin HTTP client, a status translator, and a webhook endpoint. The translator is the piece that matters most — it's what keeps the customer-facing order lifecycle (Order Journey Blueprint, §05) identical whether a PureEats rider or a Rapido rider is carrying the bag.

RapidoDeliveryProvider.javaDummy code
@Component
@ConditionalOnProperty("fulfillment.rapido.enabled")
public class RapidoDeliveryProvider implements DeliveryFulfillmentProvider {

    private final RapidoApiClient client;

    @Override
    public FulfillmentQuote quote(Order order) {
        var req = new RapidoQuoteRequest(
            order.getRestaurantLocation(), order.getDeliveryLocation(), order.getPayable());
        var res = client.getQuote(req);
        return new FulfillmentQuote(FulfillmentSource.RAPIDO, res.fare(), res.etaMinutes());
    }

    @Override
    public FulfillmentHandle handOff(Order order) {
        var req = RapidoDeliveryRequest.from(order); // pickup, drop, parcel value, our order reference
        var res = client.createDelivery(req);
        return new FulfillmentHandle(FulfillmentSource.RAPIDO, res.taskId(), null);
    }

    @Override
    public void cancel(FulfillmentHandle handle) {
        client.cancelDelivery(handle.externalTaskId());
    }

    @Override
    public FulfillmentSource source() { return FulfillmentSource.RAPIDO; }
}
RapidoApiClient.javaDummy code · endpoints illustrative
@Component
class RapidoApiClient {

    private final RestClient restClient;         // or WebClient — either fits Spring Boot 4.1
    private final RapidoAuthTokenProvider tokenProvider;

    RapidoQuoteResponse getQuote(RapidoQuoteRequest req) {
        return restClient.post()
            .uri("/v1/quotes")                        // illustrative path — confirm against Rapido's docs
            .header("Authorization", "Bearer " + tokenProvider.token())
            .body(req)
            .retrieve()
            .body(RapidoQuoteResponse.class);
    }

    RapidoDeliveryResponse createDelivery(RapidoDeliveryRequest req) {
        return restClient.post()
            .uri("/v1/deliveries")
            .header("Authorization", "Bearer " + tokenProvider.token())
            .body(req)
            .retrieve()
            .body(RapidoDeliveryResponse.class);
    }

    void cancelDelivery(String taskId) {
        restClient.post().uri("/v1/deliveries/{id}/cancel", taskId)
            .header("Authorization", "Bearer " + tokenProvider.token())
            .retrieve().toBodilessEntity();
    }
}
ExternalStatusMapper.java + RapidoStatusMapper.javaDummy code · status values illustrative
public interface ExternalStatusMapper {
    OrderStatusCode map(String externalStatus); // returns null for an unrecognized status — never guess
    FulfillmentSource source();
}

@Component
class RapidoStatusMapper implements ExternalStatusMapper {

    private static final Map<String, OrderStatusCode> STATUS_MAP = Map.of(
        "RIDER_ASSIGNED",   OrderStatusCode.RIDER_ASSIGNED,
        "RIDER_ARRIVED",    OrderStatusCode.DRIVER_ARRIVING,   // proposed state, Order Journey Blueprint §05
        "PARCEL_PICKED",    OrderStatusCode.PICKED_UP,
        "PARCEL_DELIVERED", OrderStatusCode.DELIVERED,
        "CANCELLED",        OrderStatusCode.CANCELLED
    );

    @Override
    public OrderStatusCode map(String externalStatus) {
        return STATUS_MAP.get(externalStatus); // caller must handle null — log + no-op, don't force a transition
    }

    @Override
    public FulfillmentSource source() { return FulfillmentSource.RAPIDO; }
}
RapidoWebhookController.javaDummy code
@RestController
@RequestMapping("/webhooks/rapido")
class RapidoWebhookController {

    private final RapidoStatusMapper statusMapper;
    private final OrderStatusService orderStatusService;         // existing — order-service
    private final RapidoWebhookSignatureValidator signatureValidator;

    @PostMapping("/delivery-status")
    ResponseEntity<Void> onStatusUpdate(@RequestBody RapidoStatusWebhook payload,
                                         @RequestHeader("X-Rapido-Signature") String signature) {

        signatureValidator.verify(payload, signature); // reject anything unsigned or mis-signed, before touching state

        OrderStatusCode next = statusMapper.map(payload.status());
        if (next != null) {
            orderStatusService.transition(payload.orderReferenceId(), next, "RAPIDO_WEBHOOK");
        }
        return ResponseEntity.ok().build(); // 200 regardless, so Rapido doesn't retry-storm an unmapped status
    }
}

Why the mapper is its own class and not a switch statement inside the controller: every partner speaks a different status vocabulary, but there is exactly one OrderStatusCode state machine on the PureEats side (Order Journey Blueprint, §05). One ExternalStatusMapper implementation per partner keeps that translation isolated and testable — ShadowfaxStatusMapper, PorterStatusMapper would follow the same shape without touching this one.

05

What else changes

The state machine stays one piece, but money and liability don't — these differ enough per partner that they belong on TripDetail as explicit fields, not inferred from which provider handled the order.

AspectIn-house (today)External partner (e.g. Rapido)
Rider payoutWallet credit + commission via RestaurantPayoutServiceInvoice/settlement from the partner — no Wallet entry, since PureEats doesn't employ their rider
Live locationGpsTable pings from PureEats' own rider appPartner's own tracking link or webhook payload — no GPS ping infra needed
Cancellation liabilityExisting cancellation policy, PureEats-absorbedPartner's SLA/cancellation-fee terms apply — a contract term, not an engineering default
Failure modeFalls back to AdminManualAssignmentStrategyNeeds its own fallback: quote timeout / no rider available → HybridRoutingStrategy falls through to in-house
Marginal cost signal~Zero marginal cost per order (fixed rider pool, already paid for)Real per-order cost — the exact number CostBasedRoutingStrategy compares against

Concretely: add fulfillmentSource and externalTaskId columns to the existing TripDetail entity (found in pureeats-order-service, currently in-house-only) so reconciliation, refunds, and support tooling can tell at a glance who actually delivered an order — without threading a new lookup through every consumer that reads a trip.

Design proposal with illustrative code only — nothing here was run against a real Rapido (or any partner) endpoint, and no source files in the repo were modified.
